# Digest CDS — описание проекта

**Продукт:** Digest CDS  
**Заказчик:** CDS (Chief Data Science) — руководитель DS-направления в Службе внутреннего аудита (СВА) Сбербанка  
**UI-концепция v1:** Concept 3 — Editorial UI («Digest CDS: издание»)  
**Доменный словарь:** [CONTEXT.md](../CONTEXT.md)

---

## 1. Идея

Digest CDS — корпоративный сервис сбора, структурирования и распространения знаний по новым технологиям для DS-сообщества и сотрудников СВА. Система автоматически обрабатывает внешний контент (видео с YouTube: транскрибация, русское резюме, авто-теги, эмбеддинги для поиска через FoundryModels на Cloud.ru), превращает его в **материалы** и **карточки знаний**, формирует **еженедельный дайджест** и поддерживает цикл **голосование → разбор**.

Интерфейс v1 построен вокруг метафоры **выпуска издания**: сотрудник открывает текущий выпуск, читает материалы, участвует в **цикле голосования** за тему следующего **разбора** и при необходимости углубляется в **базу знаний** или архив прошлых выпусков. Админ утверждает **shortlist дайджеста** (топ-5 после авто-ранжирования) и инициирует рассылку.

---

## 2. Проблема и ценность

### Проблема

Объём DS/ML-контента растёт быстрее, чем сотрудники СВА успевают отбирать применимое к внутреннему аудиту. Знания разрознены: часть приходит через YouTube и конференции, часть — через внутренние разборы. DS-жаргон в заголовках и материалах отталкивает сотрудников без DS-специализации; аналитики данных (SQL, BI, DQ) теряются в потоке RAG/LLM-тем; админу сложно безопасно утвердить и отправить еженедельную подборку.

### Ценность продукта

Digest CDS сокращает путь от «новая технология появилась» до «коллеги в СВА поняли и применили в аудите»:

| Роль | Ценность |
|------|----------|
| **Рядовой сотрудник СВА** | За минуту понять состав еженедельного выпуска, проголосовать за полезную тему, найти объяснение без ML-жаргона |
| **Data Analyst** | Найти практики SQL/BI/DQ, отфильтровать ML-шум, открыть материал под роль аналитика |
| **Data Scientist** | Изучить методы и эксперименты, прочитать longread разбора, скачать `.ipynb`, подготовить разбор для коллег |
| **Админ (CDS / делегат)** | Быстро triage shortlist, явно включить/исключить материалы, проверить превью письма и отправить дайджест |

### Контентный pipeline

```
YouTube → FoundryModels (транскрибация, резюме, теги, эмбеддинги)
       → Материал + карточка знаний в базе
       → Авто-ранжирование → Shortlist (топ-5)
       → Утверждение админом → Еженедельный дайджест (email + архив на сайте)
```

Сервис разворачивается на VM Cloud.ru; обработка контента выполняется через API FoundryModels в корпоративном контуре (без публичных зарубежных API).

## 3. Целевая аудитория

Доступ к сервису — только для сотрудников с **разрешённым доменом** email: `@sberbank.ru` или `@omega.sbrf.ru`.

### 3.1 Рядовой сотрудник СВА

Сотрудник Службы внутреннего аудита без DS-специализации. Хочет быстро понять, какие новые технологии релевантны аудиту: читает выпуск, голосует за тему, ищет краткие объяснения в базе знаний. Основные экраны: вход → текущий выпуск → материал / голосование / архив / база знаний.

### 3.2 Data Analyst

Аналитик данных в СВА (SQL, BI, дашборды, метрики контролей; не обучение моделей). Ищет практики отчётности и качества данных, применимые в аудите; фильтрует ML/RAG-шум. Основные экраны: база знаний с ролевыми фильтрами, материал, выпуск, голосование.

### 3.3 Data Scientist

Data Scientist в СВА (модели, эксперименты, evaluation). Готовит **разбор** победившей темы с `.ipynb`; углубляется в методы через базу знаний и longread разборов. Основные экраны: разборы, база знаний, материал, голосование.

### 3.4 Админ (CDS / делегат)

CDS или делегат: утверждает состав **shortlist дайджеста** и инициирует рассылку. Нужен быстрый triage кандидатов, превью письма и явный статус готовности материала перед отправкой. Основной экран: админ-shortlist и preview.

## 4. Ключевые функции

Функции v1 согласованы с User Story Mapping и технической спецификацией. Post-v1 (карточки с вопросами, YAML-конфиги пайплайна, публичный лидерборд) в ядро v1 не входят.

### 4.1 Вход

Корпоративная аутентификация с проверкой разрешённого домена. После успешного входа — redirect на текущий выпуск; при deep-link — возврат на исходный URL через `returnUrl`.

### 4.2 Текущий выпуск

Главный экран продукта: номер/период выпуска, заголовок издания, оглавление материалов (IssueTOC). Редакционный callout о **цикле голосования** (срок, CTA «Выбрать тему»). Под заголовками материалов — краткое «зачем СВА» (audit-dek) на языке аудита.

### 4.3 Материалы

Чтение статей и презентаций в prose-колонке с оглавлением секций (TOC). Badge формата (статья / презентация) и теги. Переход из выпуска или базы знаний.

### 4.4 Голосование

**Цикл голосования** — двухнедельное окно: один голос на пользователя, возможность сменить выбор до закрытия. Список тем с описанием на языке аудита и числом связанных материалов. Честный статус «голос не отдан» без предвыбранной темы.

### 4.5 База знаний

Семантический поиск по карточкам знаний (векторный индекс). Ролевые фильтры: Data Analyst (SQL/BI/DQ) и Data Scientist (ML, эксперименты). Честный empty state без подмены нерелевантной ML-выдачей.

### 4.6 Разборы

Список разборов и страница longread с sticky TOC. Победившая в голосовании **тема** разбирается на встрече раз в две недели; сопровождается `.ipynb`. Блок оценки качества (метрики) для DS-аудитории.

### 4.7 Админ: shortlist и рассылка

Shortlist **кандидатов дайджеста** (до 5 после авто-ранжирования): Approve / Reject, статусы draft / ready, обоснование скоринга, превью письма, отправка **еженедельного дайджеста**. Доступ только для роли админ (403 для остальных).

### 4.8 Архив

Просмотр прошлых выпусков; наполнение архива после успешной рассылки дайджеста.

### Сквозной сценарий

```
Вход → Текущий выпуск → Чтение материала
                    ↘ Голосование → Разбор (longread + .ipynb)
Админ: Shortlist → Превью → Рассылка дайджеста → Архив
База знаний → Материал (поиск по роли)
```
