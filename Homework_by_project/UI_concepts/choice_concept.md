## 2. Детальный анализ каждого концепта

### Концепт 1 — корпоративный light dashboard (Inter, card grid)

**Сильные стороны**
- Полная информационная архитектура: Главная, Дайджест, База знаний, Голосование, Разборы, Админ.
- Junior SVA (`sva-junior`) за ~30 с понял суть продукта и увидел блок голосования / «Изменить голос».
- Знакомый enterprise-паттерн снижает порог для СВА без DS-бэкграунда.
- Data Scientist смог открыть разбор и оценить структуру (код, секции, TOC).

**Слабые стороны**
- Фильтр тегов на `knowledge` фактически не работает для агента (11+ попыток выбрать `#аудит` без эффекта) — блокер для Data Analyst.
- Стартовая выдача knowledge ориентирована на RAG/ML; нет сигналов «для аналитика» vs «для DS».
- Админ: нет явных draft/ready, rationale ранжирования, batch approve/reject; «Предпросмотр письма» без отдачи.
- Senior SVA: темы и KB без plain-language «зачем аудиту»; клики по части ссылок «Презентация» падали с `BADSTRING` (битый multiline text в якорях).
- Разбор слишком поверхностный для DS (нет метрик, нет ссылки на `.ipynb`).

**Ключевые наблюдения виртуальных пользователей**
- **Daria (`sva-junior`)**: продукт понятен; не хватает one-liner «что это и для кого»; на mobile секции ниже fold без якорей.
- **Viktor (`sva-senior`)**: голосование без объяснения audit-applicability; упёрся в битую ссылку презентации в дайджесте.
- **Elena (`data-analyst`)**: дефолтный RAG-запрос отталкивает; теги/фильтры не дают найти SQL/BI.
- **Igor (`data-scientist`)**: CTA «Открыть разбор» открыл не тот материал; нет notebook link и evaluation metrics.
- **Polina (`cds-admin-junior`) / Sergey (`cds-admin-senior`)**: чекбоксы без семантики approve/reject; preview письма не работает; preview item уводит в reader-view.

### Концепт 2 — gamified dark UI (Manrope, XP/streak)

**Сильные стороны**
- Сильный визуальный характер: dark theme, XP, quest, leaderboard — выделяется среди трёх.
- Data Scientist высоко оценил квиз по RAG (гибридный retrieval и т.п.) как содержательный, а не «пустую» геймификацию.
- Сценарии вовлечения (квиз, профиль, лидерборд) хорошо ложатся на DS-сообщество.

**Слабые стороны**
- **Нет админ-shortlist** — критический пробел для сценария утверждения дайджеста (подтверждено junior и senior admin).
- Нет полноценной базы знаний / разборов / архива выпуска как у C1/C3.
- Junior SVA перегружен XP/уровнями/streak; primary action тонет.
- Senior SVA **сдался** на голосовании: карточки тем без описаний, без превью материалов, карточки не кликабельны для drill-down.
- Состояние «Ваш выбор» без сознательного голоса → недоверие и паралич решения.
- Карточки материалов на home: клики ломаются из‑за multiline/`BADSTRING` в селекторах (материал недоступен агенту).

**Ключевые наблюдения виртуальных пользователей**
- **Daria**: «Проголосовать» нашла, но pre-selected vote и жаргон тем сбили с толку → give up.
- **Viktor**: без превью контента профессиональный аудитор голос не отдаст.
- **Elena**: 10 шагов не смогла открыть карточку материала (сломанный якорь).
- **Igor**: материал + квиз — ok по глубине ML; UX-путаница in-progress vs results на одном экране.
- **Polina / Sergey**: обошли Home / Voting / Leaderboard / Profile — **ноль** moderation tools.

### Концепт 3 — editorial longread (Source Serif 4, issue-based home)

**Сильные стороны**
- Метафора «выпуска издания» считывается за секунды (`issue`): junior SVA сразу нашёл CTA «Выбрать тему →».
- Лучшая эстетика чтения дайджеста: display-типографика, warm paper, editorial callout.
- Полная IA как у C1 (Выпуск, Архив, База, Голосование, Разборы, Админ) — закрывает admin-сценарий.
- Навигация к голосованию короче и заметнее, чем «dashboard noise» C2.

**Слабые стороны**
- Те же админ-дыры прототипа: нет batch/reject, draft vs ready, «why in shortlist»; «Предпросмотр письма» и item preview ведут себя как сломанные/misleading.
- Knowledge: таксономия тегов `#RAG` / `#LLM` only; поиск «SQL / дашборды» не даёт analyst-контент → Data Analyst ушёл.
- Заголовки материалов на issue всё ещё DS-жаргон без plain-language для не-DS.
- На ballot: radio pre-selected при статусе «Ваш голос: не отдан» — противоречие.
- Razbor: для DS мелко (нет метрик, нет download `.ipynb`, несмотря на disclaimer nbconvert).

**Ключевые наблюдения виртуальных пользователей**
- **Daria**: magazine metaphor помогает; путь к голосованию очевиден; friction — pre-selected radio.
- **Elena**: KB ощущается «только для ML»; нет role/format фильтров.
- **Igor**: longread + TOC удобны, но глубина для research-to-production недостаточна.
- **Sergey**: shortlist есть (плюс vs C2), но UI не готов к безопасному send без preview и статусов.

## 3. Победитель: Концепт 3

**Итого: 46/60** (против 39 у C1 и 31 у C2).

**Обоснование (минимум 3 аргумента):**

1. **Лучшее попадание в dual-audience Digest CDS.** Junior SVA быстро понял продукт через метафору выпуска; при этом сохранены База знаний, Разборы и Админ — в отличие от C2, где модерация дайджеста отсутствует целиком.
2. **Навигация и первичный сценарий «прочитать выпуск → проголосовать»** у C3 самые чистые: один editorial home вместо перегруженного геймификацией дашборда (C2) и плотнее «журнальный» фокус, чем у корпоративного C1.
3. **Визуал и reading UX** сильнее поддерживают главный контент продукта (дайджест/материалы/разборы-as-longread), не жертвуя полнотой экранов. C1 функционально близок, но слабее по эстетике и «истории» продукта; C2 выигрывает в wow-эффекте, но проигрывает ролям Auditor и Admin.

## 4. Рекомендации по улучшению

### Что улучшить в выбранном Концепте 3
- Добавить **role-aware** вход в KB: фильтры/теги для Data Analyst (SQL, BI, DQ) отдельно от Data Scientist (ML, experiments, notebooks).
- На карточках тем и материалов — **1–2 предложения «зачем СВА / аудиту»** без жаргона.
- Админ-shortlist: явные **Approve / Reject**, статусы **draft | ready**, rationale скоринга, рабочий **email preview**, batch-действия.
- Razbor: ссылка на `.ipynb`, блок метрик/оценки, маркер конца статьи.
- Убрать противоречие **pre-selected vote** vs «голос не отдан».
- Починить multiline-текст в ссылках (избежать `BADSTRING` / «мёртвых» кликов).

### Что позаимствовать у проигравших
- **Из Концепта 1:** привычный полный nav-паттерн enterprise, явный пункт «Админ», progress цикла голосования на home, search в шапке.
- **Из Концепта 2:** опциональный слой engagement для DS (лёгкий квиз после материала, XP/streak **как вторичный** сигнал, не как главный UI); качество технических вопросов квиза; theme toggle.
