# Phase 16 Plan 02 — Strict validate-before-save with structured errors (PIPE-02)

<objective>
Fill the PipelineConfigValidator port with the real server-authoritative validator: a strict PyYAML SafeLoader subclass (syntax + duplicate keys + non-string top-level keys + empty/multi-document) plus a fixed-key Pydantic `extra="forbid"` schema (syntax + schema depth only, D-04), mapped at the adapter boundary into `PipelineConfigError(path, line?, message)` and carried by `PipelineConfigValidationError`. The PUT route returns the locked top-level `{"errors": [...]}` payload on reject with no write, and the SPA renders every error row while keeping the document dirty.

Purpose: Deliver PIPE-02 without a client-side schema (D-03/D-07) and without a silent accept.
Output: validator adapter, domain error, reject plumbing, FE error panel, and green validator/route/Playwright coverage.
</objective>
