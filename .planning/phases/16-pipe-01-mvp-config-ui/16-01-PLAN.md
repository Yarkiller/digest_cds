# Phase 16 Plan 01 — Tracer: view + save pipeline config end-to-end (PIPE-01, PIPE-03)

<objective>
Lead the phase with one production-quality end-to-end slice: an admin opens /admin/pipeline, the saved pipeline config loads into a raw YAML editor, the admin edits and saves it, and a subsequent read returns the persisted value — wired through domain → ports → use-case → thin HTTP route → SPA service → page, with storage behind PipelineConfigRepository.

Purpose: Prove the whole architectural spine (port + adapter + route + SPA boundary + page) on one real path before expanding validation depth (16-02), live persistence (16-03), and the full page surface (16-04). Validation on this path is happy-path only; strict syntax/schema validation lands in 16-02 through the same PipelineConfigValidator port.

Output: PipelineConfig domain model, two ports, two use-cases, in-memory fakes, AppContainer wiring, GET/PUT routes, pipelineConfigApi.js, a minimal AdminPipelineConfigPage.jsx, the admin/pipeline route, a Playwright happy-path test, and green round-trip + happy-path tests.
</objective>
